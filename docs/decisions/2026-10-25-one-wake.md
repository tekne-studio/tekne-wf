# The orchestrator wakes once per report and per question: the running watch delivers it, or the agent's message when none runs

**Decision:** With a `wf watch` running for the repository (`watch.pid`: its pid alive, running `watch`) and `wf spawn` behind the worktree, `ask` and `report` print no SendMessage: the watch delivers the event. With none, they print the SendMessage to the orchestrator's session, which carries the event whole (the question; the report's path), and record it as delivered in `watch.json`, so a watch started after it does not deliver it again.

**Why:** On 2026-10-25 at the site every ask and every report reached the orchestrator twice, by `watch` and by the agent's message, and each arrival rereads its whole conversation. The agent still reaches an orchestrator with no watch running, and the mark closes the gap while the orchestrator restarts its watch between two returns.

**Rejected:** Both carriers always: every event wakes the orchestrator twice. The message alone: a session in another permission mode holds it for the person's approval, a hand-over leaves it with a session that is gone, and the reminders need the watch's clock. The watch alone: an orchestrator with no watch running never hears. A new lock file: `watch.pid` already names the running watch, as one watch per repository keeps it. A grace period counting a watch that just returned as running: an orchestrator gone right after the return would never hear.
